# Map 与检索系统

Map 是 AIPD 的检索系统，不只是 `_aipd/map.md` 这个文件。

它的目标是让 Agent 从用户自然语言稳定命中相关上下文，减少乱翻、漏读和误读。

当 Agent 经常全仓搜索、读错知识域、需要多层跳转才能发现入口，或同一个业务词在文档和代码里名称不一致时查这篇。

## 三级 Map 分辨率

Map 不是另一套知识库存储，而是从不同场景观察同一批 Knowledge、README 和代码入口的声明式视图。

| 分辨率 | 回答的问题 | 典型位置 |
|---|---|---|
| 项目总 Map | 项目里有哪些主要上下文，这次任务先进入哪一条 | `_aipd/map.md` |
| 业务线 / 功能线 / shared capability Map | 当前上下文横跨哪些 Knowledge、页面、接口、规则和代码入口 | 对应 Product 功能线、Core 概念或 Engineering 能力目录中的 `map.md` |
| 局部实现 Map | 这个页面、弹窗、组件、API 或脚本内部怎样理解和修改 | 代码目录就近 `README.md` 或局部 `map.md` |

项目总 Map 要薄而完整：暴露高频入口、别名、边界、相邻关系和下一跳，不复制正文。

场景 Map 是跨知识域投影。一条“关键词发现”业务线可以同时引用 Intent 边界、Research 数据源、Core 漏斗模型、Product 功能、Engineering 规则和真实代码，而不需要把这些内容搬进同一个目录。

局部 Map 贴近实现，负责数据流、组件关系、入口文件和修改注意事项。总 Map 可以直接指向它，但不代替它解释内部细节。

关键路径要尽量扁平暴露。三级是分辨率，不是强制让 Agent 逐层点击；项目总 Map 可以为高频任务直接给出场景 Map、局部 README 或代码入口。

## 搜索是兜底，也是地图维护信号

Map-first 不禁止 `rg`、语义搜索或代码探索。它规定顺序：

1. 先用 map 命中已知权威入口。
2. 命中不清楚时再搜索核心词、页面名、接口名和权限码。
3. 搜索发现一次性线索，只用于当前任务。
4. 搜索发现稳定、高频的新入口，候选通过 Weave 回写 map。

map 的质量不是“覆盖所有文件”，而是让下一次同类任务少一次盲搜。

## 当前入口

当前 AIPD 仓库的正式项目地图入口是：

```text
_aipd/map.md
```

README 和 docs 统一使用 `_aipd/map.md`。
