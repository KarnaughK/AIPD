# Interaction Protocol

当你希望项目里的 Agent 明确区分“先讨论”与“现在执行”，并对讨论和执行交付的回复结构与长短有稳定约定时查这篇。

Interaction Protocol 是可选的项目级对话协议，不是项目认知入口。它只在初始化或 Update 时明确选择「AIPD + 四段式回复」模板后写入 `AGENTS.md`。

## Agent MD 的三种模板

`aipd-init` 初始化会处理根 Agent Entry：空项目先询问模板，有代码路径默认「纯 AIPD」。已接入项目也可随时通过 `aipd-update` 在模板间互切。

| 模板 | 安装内容 | 适合情况 |
|---|---|---|
| 不修改 `AGENTS.md` | 不写入 | 项目已有完整入口，或暂时不希望 AIPD 接管第一跳 |
| 纯 AIPD | AIPD Project Entry | 有代码项目默认推荐；规定 gate、Map-first、Case 恢复和权限边界 |
| AIPD + 四段式回复 | Entry + 四段式 Interaction Protocol | 希望「我理解」常驻做语音纠偏、「结论」高密度直出人能看懂的判断或执行结果、其余细节收拢到「可继续聊」按需追问 |

后两种模板都通过独立标记区块追加或更新，不覆盖 `AGENTS.md` 中的项目自有内容。常规 Update 会保留是否安装对话协议的选择（若旧项目仍残留历史五段式协议，会自动收敛到当前四段式权威版本）；用户明确要求换模板时（即便项目已是最新版本），`aipd-update` 支持在「纯 AIPD」与「AIPD + 四段式回复」之间原子互切。

## 它约束什么

协议先区分用户当前是在讨论还是已经给出执行指令：

- 讨论方案、提出疑问、比较取舍或明确说“先聊聊”时，只讨论，不改文件。
- 给出明确的小范围修改、运行或验证指令时，进入执行模式，直接动手。
- 执行边界不清时先短问，不猜着扩大修改。

### 统一四段式回复

讨论、问答、分析、判断、方案比较，以及执行 / 修改完成后的最终交付，统一按以下四段生成（简单问答也保留「我理解」做语音输入纠偏，不再为执行交付另起「已完成（改动 / 验证 / 说明）」模板；仅纯寒暄 / 单句确认或点名追问术语时例外）：

```text
我理解 -> 结论 -> 下一步 -> 可继续聊
```

- **我理解**：用 1–2 句复述目标与边界，专职对齐与语音纠偏。
- **结论**：高密度决策与结果区。讨论时直出最终判断、最少必要依据和关键风险前提；执行交付时用人话直出做成了什么结果、有没有实际验证通过以及关键风险 / 未做的事，不堆砌底层文件名、行号或脚本清单。
- **下一步**：优先只给一个最自然的向下动作。
- **可继续聊**：合并收拢深挖细节（包括本次具体改了哪些文件、跑了什么校验）、相邻延伸与生词词条（`[深挖]` / `[延伸]` / `[术语]`），默认只列标题或词条、不展开，按需点名追问。

执行过程中，仍按工作流用 1 句人话简短说明正在查什么或准备改什么方向，不刷屏、不抛底层实现细节；完成后统一回到四段式收尾。

## 它不约束什么

- 不替代 `_aipd/index.md`、`_aipd/map.md` 或五类 Knowledge。
- 不改变 Case Contract、phase Gate、Work Package 或外部副作用权限。
- 不要求默认长答；只有用户明确要求详细展开、方案、报告，或点名展开「可继续聊」某一项时才扩写。
- 用户当前指令或更高优先级平台规则可以覆盖它。

## 和 Agent Entry 的关系

[Agent Entry](agent-entry.md)回答“Agent 进入项目后先读什么、怎样恢复、权限边界在哪里”。Interaction Protocol 回答“Agent 怎样与你对话、何时从讨论切换到执行”。

两者可以同时装进 `AGENTS.md`，但分别使用独立标记区块，也可以只安装「纯 AIPD」。
