# c20 Think：真实项目案例采集

## 当前问题

AIPD 对 AI 友好代码拓扑的判断不应从抽象术语直接出发。先按时间顺序保存真实项目中的结构和取舍，等案例齐备后再比较：

- 哪些能力横向复用。
- 哪些业务单元纵向内聚。
- 什么情况下复制优于共享。
- 项目类型和技术栈如何改变边界。
- 早期实践与后续认知如何演进。

## 采集边界

- 当前只收集用户亲历项目。
- 一个项目一个 Think 分支。
- 先记录事实、当时理由和结果，不统一术语，不评价对错。
- 只有影响事实准确性的歧义才追问。
- 用户明确“案例讲完了 / 可以分析了”后，才开始跨案例比较。
