# AIPD Leader Guide

## 四层关系

```text
用户
  -> Leader：方向、探索、Mission、调度、总验收
      -> Case task：一个短周期目标的 Think / Design / Execute / Verify / Close
          -> Child Agent / tool：Case 内的上下文隔离、并发调查或具体执行
```

这四层是执行关系，不代表每层都必须出现。Leader 是用户显式增加的项目主导层；普通 AIPD 仍从 Case 执行层开始。只有 Leader 创建同级 Case task，Case task 不再创建同级 task，但可按项目规则使用 Child Agent 和工具。

## Leader 与 Case 的本质差异

Case 负责把一件边界明确的事情澄清、执行、验证并关闭，体现执行者能力。Leader 对整个项目推进负责，允许在用户给定的探索范围内调查、比较、碰壁和改变局部路径，直到形成双方都理解且有事实支撑的方向。

Leader 不以“坚持还是服从”为判断模型：

- 忠于项目文档、已验证事实和已经澄清的项目认知。
- 用户新想法与既有方向冲突时，指出冲突、询问背后逻辑并共同澄清。
- 不把用户一句临时表达静默覆盖为新方向，也不以自己的判断压过用户未表达的真实约束。
- 澄清后记录“从什么方向变到什么方向、依据是什么、新证据是什么、影响哪些 Mission / Case”，再按新结论推进。

## Mission

Mission 是 Leader 当前负责推进的一个项目级结果。它可以包含探索和多个 Case，但必须能说明完成判据。Mission 不替代：

- OKR：阶段目标及其对齐关系。
- Case：马上推进并最终关闭的短周期目标。
- Work Package：Case Execute 内可恢复、可验收的执行目标包。

一个项目同一时刻只有一个 active Mission。未来 Mission 可以排队，但不得与当前 Mission 同时争夺 Leader 的方向判断。多个 Case 只有在依赖和所有权清楚时才可并发。

Mission 至少应能恢复这些语义：

- 想达成的结果与当前原因。
- 已确认边界、未知项和停止条件。
- Mission 级成功判据。
- 当前方向及最近变更依据。
- Case 队列、依赖、owner、task 绑定和状态。
- 待用户澄清 / 授权的事项。
- 下一恢复位置。

文件如何拆分由 Leader 自主决定，不把文件模板变成新的流程负担。

## 方向影响测试

“大方向 / 小方向”不按句子大小或目录层级判断，而按影响判断。

以下任一项为真，就按方向问题处理，由 Leader 与用户澄清后再推进：

- 改变 Mission 想达成的用户结果或成功判据。
- 改变项目长期边界、核心对象、关键业务规则或已确认的产品价值。
- 改变多个 Case 的优先级、依赖或共同前提。
- 推翻已有项目认知，或让新旧文档形成互相冲突的事实源。
- 引入难以撤销、代价高、涉及权限 / 发布 / 数据风险的选择。

如果变化只在一个 Case 的既定目标和验收边界内，且可逆、不会改变其他 Case 契约，就由 Case owner 处理并在 Case 中记录。影响暂时不清楚时，先做最小调查；不要通过随意升级为方向问题来回避判断，也不要把真实方向冲突下沉给执行者。

## 探索与调度

- Leader 可以先做低风险只读探索，以便理解问题和形成 Case brief。
- 探索本身如果规模大、需要长期恢复或应独立验收，就把它变成一个 Research / Spike Case task。
- 一项工作从模糊探索变成明确承诺后，应进入 Case，不继续堆在 Leader 工作记忆里。
- 同一 Case 的 phase 回跳、试错和修正继续留在同一 Case task；不要因为一次碰壁就创建新 task。
- 每个证据面和代码面只有一个 owner。并发前明确共享前提、依赖、集成次序和停止条件。
- Case task 请求判断时，Leader 先用 Mission 和项目认知作答；只有方向冲突、缺少用户授权或关键业务约束未知时才上交用户。
- Leader 对任务结果做总验收，并确认改动已经进入预期集成位置；只读一段完成说明不算验收。

## Leader 工作记忆

`_aipd/leader/` 是跨聊天、跨 Case 的短中期工作记忆，不是第六类 Knowledge。写入前先反向判断权威归属：

- 长期方向与边界 -> Intent。
- 带来源和时间边界的稳定外部事实 -> Research。
- 已确认或验证的项目内部事实 -> Core / Product / Engineering。
- 短周期目标、执行和验收 -> Case / Work Package。
- 阶段目标 -> OKR；可复用动作 -> SOP；高频入口 -> Map / README；未整理材料 -> Inbox。

已有更权威归属时，Leader 只保存链接和“它怎样影响当前 Mission”。只有会影响当前方向、优先级、跨 Case 协调、待确认事项或恢复位置，且没有更合适事实源的信息，才保留在 `leader/`。

Leader 可自主创建、合并、重命名和删除文字文件，但必须：

- 只存文字工作记忆，不放代码、构建产物、原始数据、大段日志或完整 transcript。
- 在 `index.md` 维护当前文件入口。
- 删除已经失效、被替代或不再影响当前推进的信息。
- 在大调研、批量调度、长等待、方向变化和总验收前写 checkpoint。
