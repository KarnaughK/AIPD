# Leader 工作空间

> 只有显式调用 `$aipd-leader` 才创建和读取本目录。除本入口外，不预设固定文件结构。

## 定位

`_aipd/leader/` 是 Leader 的可恢复工作记忆，用来承接跨聊天、跨 Case 仍会影响当前方向、Mission、优先级、协调和下一步恢复的信息。

它不是长期 Knowledge，也不替代 Case / Work Package、OKR、SOP、Inbox、Map、局部 README 或真实代码。普通开发和普通 AIPD / Case 对话不默认加载。

## 反向归属规则

如果信息能进入更权威的事实源，就写到那里；Leader 当前仍需要时，只在这里保留链接和一句影响摘要：

- 长期方向、目标、边界与取舍 -> Intent。
- 带来源和时间边界的稳定外部事实 -> Research。
- 已确认或验证的核心模型、产品规则和跨模块工程规则 -> Core / Product / Engineering。
- 短周期事项的目标、状态、执行与验收 -> Case / Work Package。
- 阶段目标 -> OKR；可重复动作 -> SOP；高频入口 -> Map / README；未整理材料 -> Inbox。

只有同时满足下面两点，信息才留在本目录：

1. 它会影响当前方向判断、Mission、优先级、跨 Case 协调、待确认事项或下一恢复点。
2. 它目前没有更合适、更权威的事实源。

## 必须可恢复的语义

文件如何拆分由 Leader 自主决定，但当前工作区应能恢复：

- active Mission、边界、成功判据和状态。
- 用户关注方式、希望校验的阶段效果和汇报节点。
- 最近方向变化及其依据、证据和影响。
- Case 队列、依赖、owner、Codex task 绑定和状态。
- 待用户澄清 / 授权的事项。
- 下一恢复位置。

## 自主维护边界

- 只保存文字工作记忆，不放代码、构建产物、原始数据、大段日志或完整 transcript。
- 不复制其他事实源正文；使用链接和影响摘要。
- 新建、删除或重命名文件后，更新下方索引。
- 成熟信息迁往正确事实源；失效信息直接删除，不永久归档全部思考过程。

## 恢复约定

1. 先完成 AIPD 项目状态 gate，读取 `_aipd/index.md` 和 `_aipd/map.md`。
2. 再读本文件，只按“当前工作区索引”加载必要自建文件及其明确链接。
3. 恢复后先修正过时索引，再继续 Mission。
