# AIPD V2 Release Record

## 发布定位

V2 在 V1 的 Case 执行层之上增加一个只可显式启动的 AIPD Leader 层。普通 AIPD 仍由用户驾驶并以 Case 为默认执行入口；用户主动调用 `$aipd-leader` 后，当前 Codex task 才成为项目 Leader，在一个 active Mission 内探索方向、拆分和协调多个 Case task，并做总验收。

## 本版变化上下文

- 新增第十个 Skill：`aipd-leader`。`agents/openai.yaml` 设置 `allow_implicit_invocation: false`，自然语言提及、任务复杂度或多个 Case 都不能隐式激活。
- 明确四层关系：用户 -> Leader task -> Case task -> Child Agent / tool。一个 Case 对应一个同级 Codex task；Case 内部仍用 `aipd-case` 和必要 Child Agent，Case task 不创建新的同级 task。
- 新增 Mission、方向影响测试、方向变化记录、跨 Case 单一 owner 和 Leader 总验收合同。
- 新增可选 `_aipd/leader/` 工作记忆。它只在显式启动后创建，不进入基础初始化必选目录；文件结构由 Leader 自主设计，但必须能恢复 Mission、方向变化、Case / task 绑定、待确认事项和下一位置。
- 固定默认运行分工：Leader 由用户设置 `gpt-5.6-sol / max / Fast`；Leader 创建的 Case task 使用 `gpt-5.6-sol / high / Fast`。创建接口没有 Fast 字段时只记录继承或未核验状态，不虚构参数。
- Agent Entry、项目 index / map 模板和用户文档新增可选 Leader 路由，同时保留 Case 作为普通默认入口。

## 更新影响

- 项目 manifest 从 V1 更新为 V2；Schema 仍是 `aipd-project / schemaVersion 2`。
- 已存在的安全 `_aipd/leader/` 项目定制必须保留，并按 V2 的反向归属、显式启动和恢复语义做保护性合并。
- 没有 `_aipd/leader/` 的项目只更新 index / map / Agent Entry 中的可选能力说明，不自动创建目录。首次显式调用 `$aipd-leader` 时再从模板创建。
- 新增 Skill 不替代 Case / Work Package、OKR、SOP、Knowledge、Map、README 或代码事实源。

## 保护点

- 不把“用户调用 Leader”解释为发布、删除、远端写入、付费或其他外部副作用授权。
- 不自动并发多个 Leader 或 Mission；一个项目同一时刻只有一个 Leader 和一个 active Mission。
- 不用“坚持 / 服从”覆盖真实冲突。Leader 忠于项目文档和已验证事实，与用户澄清方向变化及其底层逻辑后再推进。
- 不把普通 Child Agent 冒充同级 Case task；平台缺少同级 task 能力时使用明确 fallback。
- 不因 Case task 自报完成就通过验收；Leader 仍需核对 Case 状态、真实改动、验证和集成位置。
