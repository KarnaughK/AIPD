# AIPD V1 Release Record

## 发布定位

V1 是 AIPD 第一版正式的本机有序发布快照。它把已经稳定的 Knowledge Schema v2、Map-first 检索、Case / Work Package 流程和版本驱动 Update 绑定为一个可验证整体，不为更早历史伪造版本号。

V1 同时纳入 Codex-first 发布基线：默认构建、验证和安装目标是 Codex；通用多目标架构与平台中立 fallback 继续保留，尚未实际使用和验证的平台不作为默认发布产物。

## Bootstrap 来源

- 精确两键 `{"schema":"aipd-project","schemaVersion":2}` 是安全但尚未声明完整发布版本的 `unversioned-v2`。
- 一次性 `_adoc -> _aipd` Schema 迁移完成后仍保持 `unversioned-v2`，由 Update 再应用 V1。
- 缺少版本不等于 V0；Update 选择 V1 record 作为 bootstrap 上下文。

## 本版变化上下文

- 项目 manifest 新增正整数 `aipdVersion`，与 `schemaVersion` 分工。
- 本机 `catalog.json` 成为唯一 `currentVersion` 事实源；每个项目独立记录已应用版本。
- Update 先读取版本区间记录，再读取当前权威文档和目标项目事实，一次收敛到最终态。
- `_aipd/update-log.md` 记录项目实际完成的版本跃迁、保留项与验证，不复制全局 release record。
- 普通 AIPD Skill 遇到无版本或过期项目时返回 `needs-aipd-update`；不会把它们误判为损坏，也不会局部冒充完整升级。

## 保护点

- 保留用户业务正文、Agent Entry 标记区块外内容和安全的项目自定义 Workspace 模块。
- 继续硬拒绝双根、symlink Workspace、非法 manifest、未来项目版本和文件类型冲突。
- Release Record 只解释演进，不要求把目标项目依次改成历史中间状态。
- 不访问远端；本机安装包的 V1 就是本次更新上限。

## 最终事实源

读取本记录后，必须继续读取 `../current.md` 和 `../catalog.json#currentAuthority`。若本记录中的历史描述与当前权威不同，以当前权威为最终目标。
