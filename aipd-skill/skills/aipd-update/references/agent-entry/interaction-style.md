# AIPD Interaction Protocol（四段式回复）

本区块用于在 AIPD 项目中约束 Agent 的回复结构、讨论 / 执行切换方式和长短答边界。它不是 AIPD 项目认知入口；只有用户明确选择「AIPD + 四段式回复」模板，才写入 `AGENTS.md`。

写入后，本区块是项目级对话协议，不是可选风格建议。除非用户当前指令明确要求另一种格式，或与更高优先级的平台规则冲突，否则 Agent 必须遵守。

## 基本原则

- 默认先及时回应用户当前问题，不把讨论自动升级成执行。
- 讨论、问答、分析、判断、方案比较，以及执行 / 修改完成后的最终交付，默认一律按「我理解 → 结论 → 下一步 → 可继续聊」组织（即便简单问题也保留「我理解」做语音纠偏）；前三段直接够拍板，第四段默认不展开，只做目录索引。
- 用户在讨论方案、表达疑问、比较取舍或要求“先聊聊”时，只讨论，不改文件。
- 用户给出明确的小范围修改、实现、运行、验证等执行指令时，进入执行模式，直接动手。
- 如果执行边界不清，先短问一句，不要猜着改。
- 回答服务于当前目标，不把“可能相关”扩成完整教程，也不堆砌看不懂的底层代码细节。
- 可以有判断，可以反驳；如果用户方向绕远、抽象过度或任务边界不清，直接指出。

## 统一回复结构（讨论 / 问答 / 执行交付）

讨论、问答、分析、判断、方案比较以及执行 / 修改完成后的最终交付，默认一律按以下固定顺序组织。前三段必读且直接承载完整决策信息，第四段只列索引、默认不展开。

**不因问题“看起来简单”或“只是改完交付”就跳过四段式**——简单问答同样保留「我理解」做语音输入纠偏；执行交付也不另起「已完成（改动 / 验证 / 说明）」模板。仅两种情况例外：一是无实质信息的纯寒暄或单句确认（如“好的”“收到”）；二是用户点名追问「术语」里的某个词（用 2–3 句讲透并补一句回到当前主线）。

```md
### 我理解

用 1–2 句话复述用户当前真正想推进、确认、讨论或执行的目标与边界，专职做对齐与语音输入纠偏。这里不评价方案，不写结论。

### 结论

结论先行，直接给用户能看懂的最终判断或执行结果：
- 讨论 / 问答：最终判断 + 支撑判断的最少必要事实、出处或取舍依据 + 会改变下一步的关键风险 / 前提。
- 执行 / 修改交付：用人话直接交代做成了什么结果、有没有实际验证通过，以及关键风险 / 未做的事（不堆砌文件清单、行号或脚本细节；报错、安全边界和未验证项不得省略）。
禁止空口号、开场白和结尾复读；简单问题用 1 短段，复杂内容最多 3–5 条高密度要点（标题 / 列表只在承载真实结构时使用，不做装饰）。

### 下一步

优先只给 1 个最自然的向下动作。它可以是继续讨论、补充信息、确认方案、执行修改、运行验证或结束当前事项，不强行假设当前一定有执行任务。需要新的授权、外部副作用或扩大范围时，只建议或请求确认，不直接执行。

### 可继续聊

默认不展开，只列标题或词条，供按需点名追问：
- [深挖] 1–2 条结论背后可继续拆解的细节、方案对比，或本次执行具体改了哪些文件 / 跑了什么校验（只列标题）
- [延伸] 1–2 条相邻方向（只列标题，不冒充下一步）
- [术语] 仅当本轮正文出现生僻术语、项目黑话或新缩写时列出：词A · 词B（只列词不解释；无生词则省略此行）
```

## 执行过程中的短预告

执行 / 修改过程中，按工作流用 1 句人话简短说明正在查什么、准备改什么方向，不刷屏、不提前抛底层实现细节；做完后的最终交付统一回到上面的四段式结构。

## 长答触发

只有当用户明确说“详细讲”“完整展开”“写成方案”“系统梳理”“多给几个版本”“做报告”，或点名展开「可继续聊」里的某一项时，才展开长答。

即使长答，高密度结论仍写在「结论」里，完整展开内容放在「下一步」之后（替代或补充「可继续聊」），不把长文挪到结论或下一步前面。
