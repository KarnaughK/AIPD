# Generic Leader Runtime（其他宿主同类拉起契约）

当本对话所属宿主未在 `SKILL.md` 的已知宿主列表中单列专用 `runtime/{host}.md` 时，加载本文件。

Leader 的项目主导职责本身不绑死特定 Agent 品牌。只要当前宿主具备**同类独立执行层**拉起能力（如宿主自身原生独立 task API 或终端无头 CLI），即可按以下安全契约调度；不满足条件时停止调度并与用户确认。

## 必须满足的五条底线

1. **只拉起同类宿主（Same-host only）**
   - 只使用当前对话所属宿主自身的独立任务能力或同类 CLI（例如通过本宿主自己的 CLI 参数帮助核验用法）。
   - 严禁扫描 PATH 去调用其他品牌的 Agent CLI，严禁做跨厂商拼接。
   - 严禁使用当前对话内的普通子 Agent（Child / subagent）冒充同级 Case 执行层。

2. **会话绑定与同 Case 续接**
   - 派发前先在 `_aipd/leader/` 写 checkpoint（Case brief、工作区、停止条件与返回后动作）。
   - 若当前宿主支持返回并续接独立会话 / 任务 ID：把该 ID 绑定记录到 `_aipd/leader/` 并回链 `index.md`；同一 Case 的返工、追问和 phase 回跳**必须**续接同一会话，不得新建平级 Case 或不断开新会话。
   - 若当前宿主 CLI 仅支持无状态单轮调用：派发前必须告知用户并取得同意，明确以 `_aipd/case/` 文件作为跨轮恢复的唯一事实源。

3. **模型与思考档位约定**
   - 优先遵守 `_aipd/leader/` 中记录的项目级模型 / 思考档位约定；若当前宿主支持对应参数，先核验其官方文档或 `--help` 确认真实参数与模型 ID，不得虚构字段。
   - 未记录项目约定时，沿用宿主默认模型与配置。

4. **权限与安全边界**
   - 派发只授予在既定 Case 边界内推进工作区的权限，不扩大发布、删除、远端写入、付费或其他外部副作用权限。
   - 除非用户明确授权，不要默认传入跳过全部安全检查的危险参数。

5. **能力不可达即停**
   - 若当前宿主既没有独立 task 能力，本机也未安装 / 未登录同类 CLI，则停止调度并向用户说明缺口（是补装 CLI、登录认证，还是改由用户手工开同级对话推进）。不要猜测命令强跑。

## 派发 Prompt 最低要求

发给同级 Case 执行层的 prompt 至少包含：

- “你是当前 Mission 下一个 Case 的 owner，不是 Project Leader。”
- 当前项目、Mission 摘要、Case 绝对路径（或 provisional brief）、边界、成功判据、停止条件与代码所有权。
- 先执行项目 AIPD gate，再显式使用 `aipd-case` 创建或恢复这一个 Case。
- 允许在同一 Case 内 Think / Design / Execute / Verify / Close 回跳；不得另建同级 Case 或再开一个 Leader。
- 完成后返回压缩结果：Case id / path、当前 phase、完成项、改动文件、验证结果、风险、阻塞、建议和恢复位置。

## 收口与验收

进程退出码为 0 或执行层自报完成，都不等于 Leader 验收通过。Leader 必须核对：

1. `_aipd/case/` 与 Work Package 状态与返回一致。
2. 真实代码改动落在预期工作区 / 分支且未越界。
3. 实际验证证据覆盖 Case 成功判据；缺证据则打回同一执行会话补齐。

通过后才标记为 `Leader accepted`，并更新 `_aipd/leader/` 进度。
