# Think：先看见用户结果，再命名项目记忆

## Checkpoint

- **当前问题**：现有四个入口的内容基本准确，为什么用户仍可能先看到框架术语，而不是立刻意识到 AIPD 会怎样改变下一次 AI 开发？
- **触发来源**：Case Contract；不是后续 phase 回跳。
- **边界**：只比较四个入口的现有开场、用户给出的价值逻辑和已验证文档经验；不做外部调研，不修改其他文档。
- **预期输出 / 停止条件**：明确共同价值主线、四入口职责、必须保留的准确性边界与可后置内容，然后进入 Design。
- **返回位置**：`02-design/design.md` 的需求契约、Attention Contract 和 Reduction 方案。

## 现状证据

- 根 README 首句先要求读者理解“可读取、可恢复、会持续生长的长期记忆”，随后才展开失忆问题；结果表达被内部概念抢在前面。
- docs 索引先说明“不是对象手册”和三种入口，分流正确，但没有先提醒读者每条路径最终帮助什么变化发生。
- Guide 01 从 Vibe Coding / Agent Coding 的能力演进展开，失败机制可信，但“每次重新解释、重新猜测和重复踩坑”的用户处境出现得不够集中。
- Guide 02 已有“任务前 / 中 / 后”完整循环，但开场先说系统如何工作，尚未把三段明确对应到三类可继承成果。
- 既有链接、快速开始、技术事实与“不保证 Agent 不犯错”的边界均应保留。

## 选项比较

1. **只替换术语**：把“长期记忆”换成更口语的近义词。改动小，但仍要求用户先理解概念，不能改变理解顺序。
2. **四页复制同一价值宣言**：一致性强，但会产生重复堆叠，也抹平各入口职责。
3. **共享因果主线、分别承担用户任务**：都从“上一次留下什么、下一次怎样继续”出发，但 README 负责价值识别，docs 负责意图分流，Guide 01 负责失败机制，Guide 02 负责累积机制。

## 决策

采用选项 3。共同主线固定为：新的 Agent 不必每次重新解释、重新猜测、重复踩坑；它可以继承项目判断与边界、当前任务状态、已验证经验，继续推进。读者理解这个结果后，再用“项目记忆”概括，用“AIPD”命名实现这件事的框架，最后进入机制对象。

准确性护栏：用“让 Agent 可以继承 / 更少从零开始 / 继续推进”，不用“永不出错 / 自动理解一切 / 完全无需人解释”。项目记忆不是聊天全集，也不是代码副本。

## 四入口职责

- **根 README**：最短时间呈现反复从零的处境、累积结果和三类继承对象，形成继续阅读动机。
- **docs 索引**：用户已经认可价值；按“现在想直接试、理解原因、工作中查边界”选择路径。
- **Guide 01**：用搜索正确却判断仍错、聊天中断、经验丢失的失败机制，建立问题认知。
- **Guide 02**：承接失败机制，把任务前 / 中 / 后分别解释成判断与边界、任务状态、已验证经验如何累积。

## Think 结论

- **状态**：completed。
- **未解决风险**：Leader checkout 有未提交文档改动，最终必须吸收语义小块而非覆盖整段。
- **回流位置**：Design 的需求契约、Attention Contract、四文件变更计划和 Readiness Gate。
- **使下游失效**：无；新 Case 尚无下游设计或 Work Package。
