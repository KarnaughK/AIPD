# Design：四个入口的价值优先叙事

## Design Intake

- **类型 / 模式**：docs / process，`quick`。
- **缺口**：不是事实或术语缺失，而是用户结果、概念命名与机制说明的出现顺序不对。
- **confirmed**：核心价值逻辑、三类继承对象、四入口职责、写入边界、准确性护栏和完整 phase 推进授权均由用户明确。
- **assumed**：无。
- **open**：无阻塞问题。
- **不需要**：后端、API、数据、状态机、代码拓扑或外部调研设计。

## Requirements Contract

- **problem**：新读者先面对“长期记忆 / 认知与执行系统 / 三条主线”等概念，必须先理解框架，才看到 AIPD 对自己的实际改变。
- **goal**：重排为“用户处境 -> 可见结果 -> 三类可继承成果 -> 项目记忆 / AIPD 命名 -> 机制”。
- **non-goal**：不改快速开始、后续技术事实、链接结构或产品能力；不承诺 Agent 永不出错。
- **acceptance**：根 README 前 3-5 行完成价值识别；四入口职责不同；三个继承对象明确；链接、锚点、术语、格式与范围检查通过。

## Brownfield Delta

| 文件 | 当前入口 | 设计后的职责 | Delta |
|---|---|---|---|
| `README.md` | 先定义“可读取、可恢复、会生长的长期记忆”，再列失忆症状 | 第一屏直接回答用了之后有什么不同，并给继续阅读动机 | MODIFIED：标题后至首个正文前 |
| `docs/README.md` | 先说明不是对象手册，再给三种入口 | 先确认“不要每轮从头开始”的共同目标，再按当前意图分流 | MODIFIED：开场分流说明 |
| Guide 01 | 从 Vibe Coding 到 Agent Coding 的历史变化起笔 | 先点出真实失败结果，再用原有演进和权限示例解释原因 | MODIFIED：开场与“代码/聊天/搜索”后的价值衔接 |
| Guide 02 | 先概述任务前 / 中 / 后循环 | 先承接前章，明确三类成果如何累积，再进入循环机制 | MODIFIED：开场至完整地图前 |

所有既有标题锚点、链接、示例、快速开始和后续技术事实保留。

## Attention Contract

| 入口 | 用户时刻 / 唯一主问题 | 第一眼 | 随后理解 | 自然下一步 |
|---|---|---|---|---|
| 根 README | 第一次看到 AIPD；“它能给我什么变化？” | 每次 AI 开发建立在上一次之上 | 新 Agent 可继承判断与边界、任务状态、已验证经验；这叫项目记忆 | 继续看“没有 AIPD 时”或五分钟开始 |
| docs 索引 | 已进入文档；“我现在该走哪条路？” | 不必先学完整框架，按当前意图选入口 | 体验、理解、查阅都服务于不再从头开始 | 进入完整操作卡、六章课程或按问题查阅 |
| Guide 01 | 想知道为什么需要；“Agent 已很强，问题在哪？” | 失败常来自下一次又从零开始 | 搜索能找文件却不能继承为什么；聊天与经验会断 | 接受项目需要可继承的三类内容，进入 Guide 02 |
| Guide 02 | 已理解问题；“AIPD 怎样让成果累积？” | 每轮留下三类可复用成果 | 任务前 / 中 / 后分别让判断、状态、经验继续被用到 | 进入完整地图，再到最小知识闭环 |

### 信息层级

- **now**：用户处境、累积结果、三类继承对象、各页唯一主问题。
- **next**：项目记忆 / AIPD 的概念总结与任务前 / 中 / 后因果链。
- **on-demand**：Knowledge 分类、Case phase、Skill 清单、工程机制和安装细节，留在原有后续正文。
- **remove / defer**：首屏里的框架自我介绍、重复“Agent 很会写代码”的铺垫、同义的失忆症状和过早的内部对象。
- **传播范围**：四个指定入口组成的入门路径；不扩散到其他 docs。
- **自我推翻权限**：可删除、合并、后置和重排授权开场范围内的段落；不得改目标、事实、链接或范围。
- **Verify 回跳触发器**：前三至五行仍未出现结果；内部术语与用户结果竞争；四页出现同段复制；无法一句话说清第一眼、随后理解、自然下一步；只有加法没有减法。
- **停止条件**：完整 Reduction Scan 无触发，四页可分别用一句话说明职责，继续改只会进行同义润色。

## Design Reduction Scan

- **delete**：根 README 删除过早的 slogan、三条能力清单和重复的“一句话”总结；docs 索引删除“不是对象手册”作为第一信息；Guide 开场删除对核心价值没有贡献的缓慢铺垫。
- **merge**：根 README 把三条“任务前 / 中 / 后”能力压成三类可继承成果；Guide 01 把长期事实、任务状态和经验回写归并成问题解决后的结果。
- **defer**：AIPD 的内部对象、完整循环和系统边界留到用户已理解价值后的现有正文；Guide 02 再承担机制解释。
- **reorder**：四页统一使用“处境 / 结果在前，项目记忆 / AIPD 命名在后”，但不复制文案。
- **outcome**：用户先判断这是否解决自己的重复解释与反复踩坑，再决定体验、理解或查阅，不必用术语换取价值识别。

## 文件边界与 Work Package Draft

- 一个内聚 Work Package：同步修改四个入口，因为它们共享同一价值合同，拆开会增加叙事漂移风险。
- 允许写入：四个授权文档的指定开场区块、本 Case phase 文件和 Case index 状态。
- 禁止写入：其他 docs、Skill、脚本、dist、Knowledge、运行行为和 Leader checkout。
- 运行时：Main 直接执行；范围内文本高度耦合，无并发或上下文隔离净收益，不派子 Agent。

## Readiness Gate

- 阻塞级 open：无。
- assumed 固化风险：无。
- brownfield delta、保留事实和文件边界：已明确。
- Attention Contract、Reduction Scan 入口、回跳触发器、传播范围和停止条件：已明确。
- Work Package 是单个可验收目标包，不是微步骤。
- **状态**：passed。
- **可带入 Execute 的风险**：Leader checkout 存在另一组未提交文档改动，最终集成必须按语义小块合并，不能整段覆盖。

## Design 结论

- **当前节点**：readiness-gate。
- **节点状态**：completed。
- **open / assumed**：无。
- **停止点**：Readiness Gate passed，可进入 Execute 并创建正式 Work Package。
- **恢复入口**：本文件 Attention Contract、Design Reduction Scan、文件边界与 Work Package Draft。
