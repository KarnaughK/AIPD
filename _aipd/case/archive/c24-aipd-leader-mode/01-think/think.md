# Think：Case 之上的 AIPD Leader

> 本文压缩真实讨论结论，不表示当时存在独立 Think 文件。

## 触发问题

- 普通子 Agent 的探索空间、上下文预算和阶段回跳能力有限；同级 Codex task 能加载完整 Case 和工具链，持续推进复杂目标。
- 普通 Case 已经能澄清、设计、执行和验证一件事，但它表达的是执行者能力；项目级推进还需要一个对方向、探索、跨 Case 协调和总验收负责的角色。
- 用户有两种工作模式：亲自驾驶多个 Case，或把一个项目 Mission 委托给 AI Leader。

## 关键结论

1. 普通 AIPD 默认仍停在 Case 执行层，不改变既有协作方式。
2. `$aipd-leader` 是显式覆盖层；只有用户主动调用才启动。
3. Leader 不是“坚持后服从”的角色。它忠于项目文档和已验证事实；出现方向冲突时与用户澄清底层逻辑，记录变化依据后再推进。
4. Leader 负责开放探索、方向判断、Case 拆分、同级 task 调度和总验收；Case task 负责单件事闭环。
5. Leader 工作空间只承接没有更权威归属、但会影响当前 Mission 和恢复的信息。

## 出口

- **Create / 已实现**：新增显式 Leader Skill、运行合同、工作空间边界和 AIPD V2 发布。
- **观察项**：真实 Leader 使用中会自然产生哪些文字工作记忆，以及哪些内容最终应迁出。
