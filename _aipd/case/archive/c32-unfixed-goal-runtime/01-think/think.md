## 已对齐（压缩后仍以这里为准）

1. **要做的东西**  
   给 Agent 放权，让它在范围内自己迭代一个网站。人设身份、责任、边界和方法论，不设会做完的固定任务。任务会做完，范围不会。

2. **它在 AIPD 里的位置**  
   平行于 Case / Leader 的第三套运行时。  
   Case = 有限目标，做完关闭。  
   Leader = 你委托的项目负责人，拆并调度 Case。  
   旧 Goal Mode = 绑一个 Case 少问内部 Gate。  
   本 Case ≠ 上面任何一个。

3. **记忆与状态**  
   文档是长期记忆和唯一事实源。聊天是瞬时记忆，不可靠。压缩后从本 Case 恢复，不从聊天推断。

4. **来源对话里的决策账本**  
   Agent 每次自己决策前要看：额度还够不够、周内位置、自己还剩多少上下文、有没有跑出职责。  
   死规矩：额度紧就缩小或停；额度松且快到期才敢多做；拿不准才问人。  
   这些是 Agent 醒了之后读的输入，不是代码的准入条件。

5. **先运转，后动线**  
   先让同一条对话能被代码循环拉起。状态树、分支、怎么从一态到另一态，等真跑起来再收。  
   先做框架再做动线，会被框架绑架。Case 的 phase 就是前车。章程 / 账本 / 性格可以当醒来读的输入；决策核和状态名先不封死。

6. **判断权：Agent runtime，不是 code runtime**  
   代码不做「该不该叫醒 / 该不该干活」。  
   代码只做互斥：已经有 AI 在跑 → 不管；没有 → **固定拉起同一条对话**。  
   宁愿烧 token，也不把判断劈给代码。

7. **循环和频率**  
   AI 不能关循环。循环由代码固定转。  
   AI 可以写下一档频率：  
   - 流程推进 / 持续监督：密，例如 1 分钟  
   - 等待回应：疏，例如 10 分钟  
   人进来给了东西、它又开始往下规划时，频率要回到密档。  
   **自动调回的当前理解**：人在同一条对话说话 = 门铃 / 中断，马上按推进间隔拉起；它醒了确认后把模式写成监督。不是代码猜它该不该干活。  
   20–30 秒更像互斥轮询；1 / 10 分钟才是叫醒节奏。数字未最终确认。

8. **醒来之后**  
   像人刚醒：读文件——昨天干了啥、现在在哪、什么状况、这一轮接着干还是等人做大决策。  
   进行中就别叠第二个进程。停过了就续。到了必须人拍板的节点，人读完上下文，它可以再沉寂（循环还在，只是它把频率写成等人档）。

### 每轮伪代码

```text
loop until now >= 2026-08-18 08:00:
  if worker_pid alive: sleep 20; continue          # 互斥
  if missing chat-id or prompt: sleep 20; continue
  if doorbell.flag exists: delete it               # 立刻拉起，不先睡 interval
  resume same chat-id with worker.prompt.md        # 固定拉起，不判断该不该干
  wait worker exit
  sleep max(20, interval-seconds.txt or 60)        # 可被 08:00 截断
stop
```
